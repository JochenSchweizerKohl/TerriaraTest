# TerrariaTest

This repository contains **SpawnAnchor**, a [tModLoader](https://github.com/tModLoader/tModLoader) (Terraria 1.4.4) mod. The mod adds a hand-craftable *Spawn Anchor* item that sets the player's personal spawn point to their current location (with flashy dust/sound/camera effects) and works with death respawns and the Magic Mirror.

The mod source lives in `SpawnAnchor/`. tModLoader mods are C# projects targeting `.NET 8.0`.

## Cursor Cloud specific instructions

### Toolchain locations (installed by the startup update script)
- **.NET 8 SDK**: `~/.dotnet` (`DOTNET_ROOT`). `~/.dotnet` is added to `PATH` via `~/.bashrc`; if a non-login shell doesn't see `dotnet`, run `export DOTNET_ROOT="$HOME/.dotnet"` and `export PATH="$HOME/.dotnet:$PATH"`.
- **tModLoader install**: `~/tml` (contains `tModLoader.dll` and `tMLMod.targets`). This is the headless game/build engine — there is no GUI client in this environment.
- **tModLoader data dir**: `~/.local/share/Terraria/tModLoader` (`Mods/`, `Worlds/`, `ModSources/`).

### Build (produces the `.tmod`)
- The repo root acts as the tModLoader *ModSources root*: a gitignored `/workspace/tModLoader.targets` is generated by the update script and imports `~/tml/tMLMod.targets`. The mod's `SpawnAnchor.csproj` imports `..\tModLoader.targets` (i.e. `/workspace/tModLoader.targets`), so **build from inside `SpawnAnchor/`**, not elsewhere.
- Build command: `cd SpawnAnchor && dotnet build -c Release`. `dotnet build` compiles `SpawnAnchor.dll` and then a tModLoader MSBuild target (`BuildMod` in `tMLMod.targets`) automatically packs `SpawnAnchor.tmod` into `~/.local/share/Terraria/tModLoader/Mods/` and enables it in `Mods/enabled.json`.
- Gotcha: do **not** rely on symlinking the mod into `~/.local/share/Terraria/tModLoader/ModSources/` — MSBuild resolves the symlink to the real path, breaking the `..\tModLoader.targets` relative import. Building in place at `/workspace/SpawnAnchor` (with `/workspace/tModLoader.targets` present) is the working setup.
- There is no separate "lint" step; the C# compiler warnings/errors from `dotnet build` are the lint signal. (The `tModLoader.CodeAssist` analyzers are intentionally not referenced so builds work offline.)

### Run / verify (headless)
- No GUI Terraria client is available, so the visual effects (dust, sound, camera, actual respawn) can only be fully verified in a graphical tModLoader client, not here.
- The strongest headless verification is loading the mod in the **dedicated server**, which registers all content (item, recipe, `ModSystem` detour, localization):
  ```
  cd ~/tml
  dotnet tModLoader.dll -server -nosteam -autocreate 1 -worldname TestWorld \
    -world "$HOME/.local/share/Terraria/tModLoader/Worlds/TestWorld.wld" \
    -players 8 -port 7777 -password "test123"
  ```
  A clean load prints `Adding Content: Spawn Anchor v0.1` ... `Server started`. Run it in tmux and stop it by sending `exit` to the server console (never kill by process name).

### Mod design notes (non-obvious)
- Setting a spawn to an arbitrary tile via `Player.ChangeSpawn` alone is silently rejected on respawn by vanilla `Player.CheckSpawn` (which requires a bed). `Systems/SpawnValidationSystem.cs` installs an `On_Player.CheckSpawn` detour that whitelists the anchor stored per-world in `Players/AnchorPlayer.cs`. Both pieces are required for respawn to actually honor the anchor.
- The item uses the vanilla Magic Mirror texture (`Texture => "Terraria/Images/Item_" + ItemID.MagicMirror`) so no `.png` asset is needed.
